Create `.planning/phases/03-cutover-and-verification/cutover.sh` -- the cutover script that updates Docker Desktop settings and starts Docker from the external volume. Follow Phase 1/2 conventions exactly.

**Script structure (top to bottom):**

1. **Shebang and strict mode:** `#!/bin/bash` then `set -euo pipefail`

2. **Header comment:** Purpose, requirements covered (CONF-01, CONF-02), safety notes. Mention this is irreversible in that it changes Docker's data location.

3. **Constants:**
   - `SETTINGS_DIR="$HOME/Library/Group Containers/group.com.docker"`
   - `SETTINGS_STORE="$SETTINGS_DIR/settings-store.json"`
   - `SETTINGS_JSON="$SETTINGS_DIR/settings.json"`
   - `NEW_PATH="/Volumes/Unitek-B/Docker"`
   - `DOCKER_RAW="$NEW_PATH/Docker.raw"`
   - `TIMEOUT=120`
   - `INTERVAL=5`
   - `PASS=0` / `FAIL=0`

4. **Helper functions** (same pattern as preflight.sh):
   - `cutover_pass()` / `cutover_fail()` / `cutover_info()` with `[ PASS ]` / `[ FAIL ]` / `[ INFO ]` format and PASS/FAIL counters
   - `cutover_abort()` with ABORT message and exit 1

5. **emit_diagnostics function** (per D-12):
   - Print separator: `=== Diagnostic Information ===`
   - Print settings-store.json DataFolder value using: `python3 -c "import json; d=json.load(open('$SETTINGS_STORE')); print(d.get('DataFolder','NOT FOUND'))"`
   - Print settings.json dataFolder value using: `python3 -c "import json; d=json.load(open('$SETTINGS_JSON')); print(d.get('dataFolder','NOT FOUND'))"`
   - Print Docker Desktop logs location: `$HOME/Library/Containers/com.docker.docker/Data/log/host/`
   - Print last docker info output: `docker info 2>&1 | head -30 || true`
   - Print separator: `=== End Diagnostics ===`

6. **Print header:** "Docker Desktop Cutover" with `=` separator line

7. **Docker-stopped guard** (same as Phase 1/2):
   - Check for Docker processes using pgrep: `pgrep -f 'Docker Desktop|com.docker.backend|com.docker.virtualization|com.docker.helper|com.docker.build'`
   - If any found: `cutover_abort "Docker is still running. Stop Docker Desktop first."`
   - If none found: `cutover_pass "No Docker processes running"`

8. **External volume guard:**
   - Check `test -f "$DOCKER_RAW"` -- the Phase 2 copy must exist
   - If missing: `cutover_abort "Docker.raw not found at $DOCKER_RAW -- run Phase 2 first"`
   - If present: `cutover_pass "Docker.raw found at $DOCKER_RAW"`

9. **Settings files guard:**
   - Check `test -f "$SETTINGS_STORE"` -- settings-store.json must exist
   - Check `test -f "$SETTINGS_JSON"` -- settings.json must exist
   - Abort if either missing

10. **CONF-01: Update settings files** (per D-01, D-02, D-03, D-04, D-13):
    - Use an embedded Python script via `python3 - <<'PYEOF' ... PYEOF`
    - The Python script must:
      a. Import json, sys, os
      b. Define `update_datafolder(settings_path, new_path, key_name)` function that:
         - Opens and parses the JSON file (abort on FileNotFoundError or JSONDecodeError)
         - Updates the specified key to new_path
         - Writes back with `json.dump(data, f, indent=2)`
         - Reads back and verifies the value matches (D-04 readback verify)
         - On any error: print to stderr and sys.exit(1)
      c. Call for settings-store.json with key `DataFolder` and value `/Volumes/Unitek-B/Docker`
      d. Call for settings.json with key `dataFolder` and value `/Volumes/Unitek-B/Docker`
      e. Print "OK" on success
    - Capture Python exit code. If non-zero: `cutover_fail "CONF-01: Settings update failed"` then `emit_diagnostics` then `cutover_abort "Settings update failed -- Docker config unchanged, safe to investigate"` (per D-13 hard-stop)
    - If zero: `cutover_pass "CONF-01: DataFolder updated to /Volumes/Unitek-B/Docker in both settings files"`

11. **CONF-02: Start Docker Desktop and poll for readiness** (per D-05, D-06, D-07):
    - `cutover_info "Starting Docker Desktop..."`
    - `open -a "Docker Desktop"`
    - Initialize `ELAPSED=0`
    - Poll loop: `while [[ $ELAPSED -lt $TIMEOUT ]]; do`
      - `if docker info > /dev/null 2>&1; then` break with success
      - `printf "\r[ INFO ] Waiting for daemon... %ds/%ds" "$ELAPSED" "$TIMEOUT"`
      - `sleep $INTERVAL`
      - `ELAPSED=$((ELAPSED + INTERVAL))`
    - `printf "\n"` after loop
    - If timeout reached: `cutover_fail "CONF-02: Docker daemon not ready after ${TIMEOUT}s"` then `emit_diagnostics` then `cutover_abort "Docker did not start in time. You can wait and re-run verify-cutover.sh manually."`
    - If ready: `cutover_pass "CONF-02: Docker daemon ready after ${ELAPSED}s"`

    - Note: DockerRootDir may show VM-internal path like /var/lib/docker (Open Question 2 from research). This is informational only -- the real check is that settings files point correctly (already verified in step 10).

13. **Save cutover results to cutover-results.txt** in the same directory:
    - Redirect a summary block to `.planning/phases/03-cutover-and-verification/cutover-results.txt`
    - Include: timestamp, settings update status, Docker readiness status, DockerRootDir value

14. **Summary:**
    - Print total PASS and FAIL counts
    - If FAIL > 0: exit 1
    - If FAIL == 0: Print "Cutover complete. Run verify-cutover.sh to confirm data integrity."

**Script structure:**

1. **Shebang, strict mode:** `#!/bin/bash` then `set -euo pipefail`

2. **Header comment:** Purpose, requirements covered (VERIF-01, VERIF-02, VERIF-03), note that Docker must already be running, note this is read-only and safe to re-run.

3. **Constants:**
   - `NEW_PATH="/Volumes/Unitek-B/Docker"`
   - `SETTINGS_DIR="$HOME/Library/Group Containers/group.com.docker"`
   - `SETTINGS_STORE="$SETTINGS_DIR/settings-store.json"`
   - `PASS=0` / `FAIL=0`

4. **Helper functions:** `verify_pass()` / `verify_fail()` / `verify_info()` with `[ PASS ]` / `[ FAIL ]` / `[ INFO ]` format and PASS/FAIL counters

5. **Print header:** "Cutover Verification Results" with `=` separator

6. **Docker daemon guard:**
   - Check `docker info > /dev/null 2>&1`
   - If docker info fails: print `[ FAIL ] Docker daemon is not running. Start Docker Desktop first or run cutover.sh.` and exit 1
   - If succeeds: `verify_pass "Docker daemon is running"`

7. **Settings verification (CONF-01 confirmation):**
   - Read DataFolder from settings-store.json via Python: `CURRENT_DF=$(python3 -c "import json; d=json.load(open('$SETTINGS_STORE')); print(d.get('DataFolder','NOT FOUND'))")`
   - If `$CURRENT_DF` equals `/Volumes/Unitek-B/Docker`: `verify_pass "CONF-01: DataFolder = /Volumes/Unitek-B/Docker"`
   - Else: `verify_fail "CONF-01: DataFolder = $CURRENT_DF (expected /Volumes/Unitek-B/Docker)"`

8. **Docker Root Dir check (informational -- per Open Question 2 from research):**
   - `DOCKER_ROOT=$(docker info --format '{{.DockerRootDir}}' 2>/dev/null || echo "unknown")`
   - `verify_info "Docker Root Dir: $DOCKER_ROOT"`
   - This is informational only (may show VM-internal path)

9. **VERIF-01: Image count > 0** (per D-10):
   - `IMAGE_COUNT=$(docker images --format '{{.Repository}}' | wc -l | tr -d ' ')`
   - If count > 0: `verify_pass "VERIF-01: $IMAGE_COUNT image(s) present"`
   - If count == 0: `verify_fail "VERIF-01: No images found -- migration may have failed"`
   - Also print first 10 image names with verify_info for user reference

10. **VERIF-02: Container count > 0** (per D-09, D-10):
    - Use `docker ps -a` (all containers, not just running -- per D-09 broken Compose group is expected)
    - `CONTAINER_COUNT=$(docker ps -a --format '{{.Names}}' | wc -l | tr -d ' ')`
    - If count > 0: `verify_pass "VERIF-02: $CONTAINER_COUNT container(s) present"`
    - If count == 0: `verify_fail "VERIF-02: No containers found -- migration may have failed"`
    - Print first 10 container names with verify_info

11. **VERIF-03: hello-world smoke test** (per D-10):
    - First check if hello-world is cached: `docker images --format '{{.Repository}}' | grep -q '^hello-world$'`
    - If cached: `verify_info "hello-world image already cached locally"`
    - If not cached: `verify_info "hello-world not cached -- will pull from registry (requires network)"`
    - Run: `docker run --rm hello-world > /dev/null 2>&1`
    - If exit 0: `verify_pass "VERIF-03: hello-world smoke test succeeded"`
    - If non-zero: `verify_fail "VERIF-03: hello-world smoke test failed"` then `verify_info "Run manually: docker run --rm hello-world"`

12. **Summary:**
    - Print total PASS and FAIL counts
    - If FAIL > 0: print "VERIFICATION FAILED" and exit 1
    - If FAIL == 0: print "All checks passed -- Docker is running from external volume. Safe to proceed to Phase 4 (cleanup)." and exit 0

Make executable: `chmod +x`.

This script is READ-ONLY regarding Docker configuration. It runs docker commands but does not modify settings files, start/stop Docker, or delete anything. Safe to re-run at any time.
